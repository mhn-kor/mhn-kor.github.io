# 자동빌드 기회비용 비교 상세 설계

작성: 2026-10-14. 상태: 사용자 확정3건 및 제한된 교체·연성 비교를 실행 연결. 아래 설계 원칙과 실제 제한 범위는14절에서 구분한다. 상위 기준: [AUTO_BUILD.md A0](AUTO_BUILD.md#a0-기회비용을-고려한-장비-선택).

## 1. 목적·범위

- 장비 단품이 아니라 장비를 채용한 전체 구성과 대체·보완한 전체 구성을 비교한다.
- 기존 무기/스타일 지침·공식 스킬 수치·공유 계산을 활용한다. 고정 스킬 점수표를 새로 요구하지 않는다.
- 무기·몬스터·스타일·강화·파라미터·탄 운용·사용자 필수 조건은 같은 비교 묶음에서 고정한다.
- 자동빌드 생성 내부에서만 장비·연성을 재구성한다. 기존 내 빌드·사용자 보유 연성은 변경하지 않는다.
- 수치 비교는 현재 계산 모델의 효율이다. 실제 DPS·실전 최적·모든 조합의 최적해를 주장하지 않는다.
- 단품 선별, 전체 점수, 기회비용 증거를 구분한다. 단품 스킬 합이나 고룡 부위 수를 최종 효율로 쓰지 않는다.

## 3. 정책 데이터: 계산 전에 기준 확정

### 3.1 분류

| 분류 | 처리 | 예시 |
| --- | --- | --- |
| hard: 확정 필수 | 후보 자격; 미달이면 탈락 | 록온1, 실드태클 가드5, 사용자 직접 올린 최소 |
| soft: 우선 투자 | 미채용~권장 목표 탐색; 확보량 자체에 피해 보너스 없음 | 고룡·속성·회심격·흉회심 |
| operation: 점수 밖 운용 | 지침에 명시된 별도 효과/레벨을 비교 | 반사, 필요한 수준의 가드·SP 회복·강화 지속 |
| conditional: 적용 범위 | 고정된 조건 묶음에서만 실제 효과 계산 | 변형 공격, 모으기, 상태 축적, 특정 탄 강화 |
| avoid: 비권장 | 자동 투자 우선순위 낮춤/제외; 겸용 장비 허용 | 저스트가드 가드 성능, 스텝샷 반동 |
| unavailable/unknown | 적용 불가와 자료 미확인을 구분 | 무관한 상태 축적 위력 / 미확인 스타일 효과 |

- 한 스킬이 여러 분류에 속할 수 있다. 가드2 필수·3 권장처럼 최소와 추가 투자를 분리한다.
- 1·2·3순위는 탐색 순서·후보 보존에 사용한다. 실제 피해 증가나 최종 확보 보상으로 환산하지 않는다.
- 회심 활용 방향은 강화·파라미터를 포함한 무기 자체 회심을 바탕으로 투자해볼 만한 방향이다. 80%를 필수 또는 고정 목표로 두지 않는다. 추가 회심·회심격·슈퍼회심과 다른 투자의 전체 구성 효율을 비교하며, 80% 미만이라는 이유로 탈락시키지 않는다.
- 반사처럼 hard 최소와 operation 목표가 함께 있는 스킬은 최소를 지킨 뒤 추가 레벨의 점수 손실을 비교한다.
- W7의1~8순위와 W6의 장비 평가도 탐색 보조다. 새 고정 피해 가중치가 아니다.
- 무기/스타일별 지침 미제공 영역은 공통 규칙만 사용하며 확인된 부분과 미지원 부분을 표시한다.

### 3.2 정책 객체(데이터 양식 제안)

```js
policy = {
  contextKey, ruleVersion, dataVersion,
  hard: [{ skill, min, sourceRule }],
  investments: [{ skill, from: 0, target, priority, sourceRule }],
  operation: [{ skill, usefulLevels, target, sourceRule }],
  dependencies: [{ skill, level, needs }],
  assumptions: [{ id, effects, conflicts, sourceRule }],
  discouraged: [{ skill, reason, sourceRule }],
  unknown: [{ subject, reason }]
};
```

문서를 브라우저에서 읽어 AI가 해석하는 구조는 아니다. 개발 시 지침을 위 데이터로 연결하고 문서 규칙 ID와 테스트를 함께 관리한다. 새 장비 수치·스킬·슬롯은 기존 정책 안에서 자동 평가; 새 효과·새 플레이 원리는 정책/파서 업데이트가 필요하다.

## 4. 빌드 평가값: 하나의 가중합을 만들지 않음

빌드 B마다 아래 평가 결과를 생성한다.

```text
valid(B) = 모든 확정 필수·장비/연성 제한·적용 조건 충족
Sactive(B) = 기존 공유식으로 계산한 동일 조건 발동 비교 점수
Sbase(B) = 선택적 전투 조건을 끈 기준 점수(보조 비교 축으로 확정)
U(B) = 명시된 점수 밖 운용 효과별 유효 수준 벡터
C(B) = 실제 사용한 연성 칸 수
I(B) = 핵심·고룡·속성 등 투자 구성(탐색/설명용, 우열 점수 아님)
```

- 장비의 모든 유효 공격 효과는 S에 이미 포함한다. 고룡·추격 등 가중치를 또 더하지 않는다.
- C를 S에서 빼지 않는다. 연성 때문에 놓친 공격 효과는 실제 구성의 S에 반영되어 있으며 이중 차감 금지.
- 빈 슬롯 수 자체를 공격/추천 보너스로 만들지 않는다. 필요 슬롯의 성립 여부, 실제 소모 C, 남은 슬롯은 각각 검사/비교/설명한다.
- U는 실제 레벨/단계이며 100점으로 바꾸지 않는다. 가드 최선 단계 이후·권장 목표 초과는 추가 우대하지 않는다.
- 강화 지속 등 서로 다른 운용 효과 간 우열은 임의 합산하지 않는다. 적용 범위 미확인이면 U의 확정 축으로 사용하지 않는다.
- 상태 축적 수치·발동 확률·반사 피해 등 미모델링 효과를 S에 임의 추가하지 않는다. 상태 축적 위력은 현 계산의 평균 확률 보정 미완료를 표시한다.

### 조건부 효과 처리

- 기존 발동 가정 점수 Sactive는 유지한다. SP 위력OFF·무기/탄 적합성·불퇴전ON/매진OFF 등 기존 확정 예외 유지.
- Sbase는 실제 가동률 가정 없이 별도 열로 표시한다. 두 점수의 평균을 실전 점수로 만들지 않는다.
- 서로 양립 불가능한 효과는 같은 시나리오에서 켜지 않는다. 조합이 미확정이면 별도 가정/한계로 표시한다.
- 스타일 고유 공격/가드 성공 조건의 ON/OFF는 동일 비교 쌍에 똑같이 적용한다. 운용 자체가 다르면 별도 비교 그룹이다.
- 모으기·변형 효과를 전체 공격의 상시 효과로 확대하지 않는다. 해당 공격 점수라는 라벨과 미확인 사용 비율을 남긴다.

## 5. 후보 생성: 초기에 버린 장비도 다시 검토

### 5.1 초기 구성

1. 전체 등록 장비의 스킬·슬롯·선행조건·적합성을 색인한다.
2. 초기 후보는 필수 조건 담당, 핵심 투자별, 공격 효율, 운용 보완, 선행조건 묶음 경로에서 고르게 확보한다.
3. 초기 제한 탐색으로 여러 완성 빌드를 만든다. 단품 평가에서 낮았던 장비를 영구 제외하지 않는다.
4. 장비/스킬 수준이 완전히 같고 관련 메타데이터도 같은 경우만 동등 후보로 압축한다. 부분 구성의 낮은 점수만으로 경지/조합 가능성을 제거하지 않는다.

### 5.2 전체 구성 교체·보완

각 기준 빌드 B와 부위 p, 대체 장비 e에 대해 다음 세 경로를 만든다.

| 경로 | 재구성 범위 | 목적 |
| --- | --- | --- |
| 직접 교체 | p 교체 + 모든 자동 연성 재탐색 | 부위 교체 후 슬롯·투자 재분배 |
| 부족분 보완 | p 교체 + 부족 스킬 공급 부위1개 교체 + 연성 재탐색 | 잃은 필수/유용 효과를 다른 부위로 이동 |
| 연계 재구성 | p의 e를 고정하고 나머지4부위 제한 탐색 + 연성 | 한 부위씩 바꾸면 손해지만 여러 부위 조합은 유리한 안 발견 |

- 공급 부위는 스킬 색인으로 찾는다. 특정2부위를 미리 고정하지 않는다.
- 순수 필수 복구 외에도 권장 스킬 유지/축소/포기를 비교한다. 잃은 권장을 모두 복구하면 다른 강제가 되므로 금지.
- 경지5+1 등 선행조건은 묶음 후보로 생성한다. 중간 단계의 점수가 안 오른다는 이유로 묶음을 제거하지 않는다.
- e의 선택지는 전체 등록 목록에서 후보 경로별로 균등하게 뽑는다. 전 목록 평가를 끝내지 못하면 미검토 수를 기록한다.
- 개선/새로운 장점을 가진 결과를 다음 라운드의 기준으로 사용한다. 2~3라운드는 초기 실험값이며 이후 성능 검수로 조정.
- 장비가 특정 빌드에서 탈락해도 다른 무기/구성에서 금지하지 않는다.

### 5.3 연성 재탐색

1. 자동 생성 연성을 지우고 장비 기본 스킬+무기 스킬을 다시 집계한다.
2. 필수 부족량 d(s)=max(0, hardMin(s)−baseLevel(s)) 계산.
3. 연성 불가 스킬이 부족하면 장비 보완 경로로 넘긴다. 가능한 스킬도 총 필요량이 빈 칸 수를 넘으면 현 장비 구성은 불가.
4. 각 연성 스킬의 0~필요/권장 레벨과 선행조건 묶음을 상태로 탐색한다. 선택 한 칸의 즉시 점수 증가만 보지 않는다.
5. 정렬 순서가 다른 같은 스킬 개수 조합은 한 상태로 압축한다. 슬롯당Lv1·총 슬롯·레벨 상한을 검사한다.
6. 제한 폭 안에서 공격 효율·운용 수준·적은 연성 비용·묶음 투자 상태를 보존한다. 제한으로 빠진 상태는 최적이라고 단정하지 않는다.
7. 선택한 스킬 개수 조합을 실제 부위 슬롯에 배치한다. 같은 기본 스킬 부위 우선, 부족하면 다른 부위 사용.

기존 사용자가 저장한 연성을 지우는 기능이 아니다. 이번 자동 생성 후보의 연성만 재계산한다. 실제 등록 표류연성 스킬만 사용하고 장비 레벨을 빼거나 다른 파라미터로 교체하지 않는다.

## 6. 기회비용 계산식·비교 확정

### 6.1 같은 가정의 두 완성 빌드 비교

```text
ΔSactive = Sactive(대체·보완안) − Sactive(채용안)
ΔSbase   = Sbase(대체·보완안) − Sbase(채용안)
ΔU       = 운용 수준의 항목별 차이
ΔC       = 사용 연성 칸 수의 차이
```

- ΔS만으로 운용 가치의 손실을 상쇄했다고 선언하지 않는다.
- 추격 손실·고룡 증가 등 개별 효과를 따로 계산해 합치지 않는다. 상호작용·선행조건을 포함한 완성 빌드 점수 차이가 기준이다.
- 점수 밖 효과는 획득/유지/손실로 설명하고 정확한 피해 기여는 미확인으로 남긴다.

### 6.2 명백한 우열(지배 관계)

같은 정책·가정, 유효한 두 빌드에서 A가 B보다 다음 모든 항목에서 나쁘지 않고 하나 이상 좋으면 B를 추천 후보에서 제거한다.

```text
Sactive(A) >= Sactive(B)
Sbase(A)   >= Sbase(B)
Uj(A)      >= Uj(B)        // 확인된 운용 축마다
C(A)       <= C(B)
그리고 하나 이상 엄격히 유리
```

- 장점이 서로 갈리면 우열 미확정: 둘 다 대안으로 유지한다. 임의 환산 점수·허용 손실률을 만들지 않는다.
- 계산에서 빠져 있지만 지침에 유용함이 명시된 미확인 운용 차이는 동등하다고 간주하지 않는다. 별도 미확인 후보로 보관하고 검증 전 권장 단정 금지. 적용 불가·무관한 내성 등 이미 무효로 분류한 차이는 별도 장점으로 만들지 않는다.
- 동등하면 W6의 실제 연성 재사용 배치·W7의 비권장/우선순위·결정적ID 순으로 대표 선택. 같은스킬 배치만 바뀐 후보를 여러 개 추천하지 않는다.
- 표시 반올림으로 우열을 결정하지 않는다. 내부 원값 사용이 어려운 현 공유식에서는 현재 정수 점수 동률로 취급하고 초정밀 차이를 주장하지 않는다. 실수 오차 허용은 수치 안정성용이며 게임 효율 가중치가 아니다.

### 6.3 장비의 상대적 가치: 고정 점수표 없음

부위 p의 e를 사용하는 집합과 사용하지 않는 집합을 동일 예산·가정으로 탐색한다.

```text
Pwith(p,e)    = e를 사용한 완성 후보들의 우열 미확정 집합
Pwithout(p,e) = e를 쓰지 않고 재구성한 후보들의 우열 미확정 집합
```

- 같은 운용 수준을 유지한 안 중 관측 최고 점수끼리 차이를 비교하면 장비의 공격 기회비용을 설명할 수 있다.
- e 사용안의 장점을 대체안이 전부 유지하면서 더 좋으면 e는 그 문맥에서 교체 후보다.
- e를 빼면 반사 등 장점을 유지할 수 없으면 점수 손해와 운용 이득을 함께 제시한다.
- 비교안이 없다는 것이 장비 필수를 증명하지 않는다. 확인한 연성/스킬 부족은 ‘해당 구성에서 보완 불가’, 시간·폭 부족은 ‘대안 미발견’으로 구분한다.
- 기회비용 설명은 탐색에서 관측한 차이다. 전역 최적 대체안과의 차이라고 부르지 않는다.

## 7. 추천 최대5개 선정

1. 필수 미충족 제거, 같은 장비+유효 스킬 구성 중복 압축.
2. 6.2의 명백히 열등한 후보 제거. 남은 장단점 집합에서 선택.
3. 기본 대표는 동일 조건 발동 점수 최고 후보. 운용 필수는 이미 충족해야 함.
4. 점수 밖 운용을 더 확보한 후보, 적은 연성 비용 후보, 조건OFF 점수가 유리한 후보를 각각 검토한다.
5. 운용 레벨별 확보에 필요한 점수 손실을 계산해 중간 투자 후보도 검토한다. 숫자 근거 없이 특정레벨을 ‘균형 최적’이라고 부르지 않는다.
6. 같은 대표가 여러 역할을 충족하면 중복 제외. 남은 자리는 교체 근거가 다른 후보 중 점수 순으로 선정; 의미 없는 다섯개 채우기 금지.

- 일반 핵심 레벨이 많다는 이유만으로 추천 자리를 보장하지 않는다. 고룡3도 미채용도 강제하지 않는다.
- 최종 후보에는 실제 장점이 있어야 한다. 낮은 점수·같은 운용·더 많은 연성의 후보를 투자 다양성이라는 이유만으로 추천하지 않는다.
- 5개를 넘는 운용 축이 충돌하면 각 축 대표를 모두 보여줄 수 없다. 미노출 대안 수와 상세 보기/정렬로 확인 가능하게 한다. 단일한 ‘최적의 절충’은 사용자 선호 없이 확정 불가.
- 점수순은 순수 Sactive 내림차순. 운용·투자 비교는 대표 역할별 표시이며 점수순으로 오인시키지 않는다.

### 고룡·랜스·보우건

- 고룡: 부위별 다른 스킬과 고룡 선행/중첩 효과를 전체 식으로 계산. 고룡 추가 때문에 잃은 유효 효과도 대체안에 포함.
- 랜스: 확정 가드/불퇴전/반사 최소 유지. 반사 추가레벨의 피해 환산 없이 추가 확보에 따른 실제 공격 점수 손실을 표시.
- 보우건: 주력탄·장전/반동/회피장전 요구를 고정하고 재구성. 스텝샷/슬라이딩/가드리로드/앉아쏘기의 대체 조건을 다른 스타일에 복사하지 않음.

## 10. 부하·중단·범위 표시

- 완성 빌드의 교체 재탐색을 모든 조합에 무제한 중첩하지 않는다. 초기 대표→교체 검토→새 대표 순으로 제한 라운드 진행.
- 초기 실험 예산: 전체 실제 점수 평가6,000회 이내, 기존8초 상한 유지. 단계별 예산은 초기2,400/교체2,400/최종 근거1,200으로 예약하되 미사용분 이월. 게임 가치 가중치가 아니라 개발 성능 설정이다.
- 연성 내부 상태 확장·전체 장비 스캔·증거 탐색도 같은 시간 예산을 소비한다. 점수 횟수만으로 부하가 제한된다고 주장하지 않는다.
- 24/160 등의 초기 폭, 연성 상태 폭·기준 빌드 수는 PC/모바일 측정 후 확정한다. 위 수치에서 충분한 근거가 나오는지 현재 보장하지 않는다.
- 재계산 캐시·동등 상태 압축·불가능 필수 가지치기로 낭비를 줄인다. UI 양보 또는Worker 사용은 실제 모바일 측정 후 선택한다.
- 제한 도달 시 이미 확보한 유효 결과를 반환한다. 교체검사 미완료 결과는 ‘기회비용 검토 일부 미완료’로 표시하며 완료로 꾸미지 않는다.
- 진행: 초기 구성/교체·보완/연성 재분배/최종 비교 단계와 검사한 장비·구성·유효 후보 수 표시. 7,000~10,000은 고정 목표/품질 보증 아님.

## 12. 사용자 확인으로 확정한 사항

근거: 2026-10-14 사용자 답변. 아래 결정은 설계에 반영됐으며 실행 반영은 별도다.

1. 조건ON 점수 유지 + 조건OFF 점수를 보조 비교 축으로 추가. 임의 가동률·혼합 DPS 없음.
2. 기본 추천은 공격 고점/운용 보완/연성 저투자 등의 역할별 최대5개. 서로 다른 장점을 한 점수로 합치지 않음.
3. 회심80% 하드 조건 폐기. 80%를 권장 목표로 치환하지도 않음. 자체 회심이 높아 회심 투자를 검토할 만한 방향이며, 실제 투자 수준은 전체 구성의 기회비용으로 결정. 추가 회심이 없는 안도 비교.

추가 미확정: W11 회피근접의 모으기 효과, W12 비상용검 상태이상 예외·병 축적 기준·앙갚음 수치, 보우건5종 자료누락. 이번 설계에서 임의로 확정하지 않는다. 지침 연결표를 만들고 확정된 부분부터 적용·검수한다.

## 14. 실제 실행 연결·범위
