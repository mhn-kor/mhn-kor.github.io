# 무기·스타일

무기 동작(무기 특성)과 무기별 운용 가이드의 목차. 정비: 2026-10-16.

- 문서 지도: 로직 [AUTO_BUILD.md](AUTO_BUILD.md) / 빌드 컨셉 [CONCEPTS.md](CONCEPTS.md) / 스킬 [SKILLS.md](SKILLS.md) / 무기별 운용 가이드 [weapons/](weapons/)

## 세 문서의 역할

| 문서 | 묻는 것 | 성격 |
| --- | --- | --- |
| **무기 특성** (이 문서) | 이 무기·스타일의 주요 딜 메커니즘에 어떤 **동작**이 있나? | 게임 구조 사실. 스킬 이름을 쓰지 않는다 |
| **운용 가이드** (`weapons/*.md`) | 이 스타일로 **어떻게 플레이하고**, 어떤 스킬을 쓰고/안 쓰나? | 사용자 운용 지침 (서술형을 요약) |
| **스킬 사전** ([SKILLS.md](SKILLS.md)) | 이 스킬은 **어떤 동작·상황**에서 발동하나? | 공식 효과 + 조건 코드값 |

빌드할 때 읽는 순서: ① 무기 특성으로 액션 조건이 맞지 않는 스킬 제외 → ② 운용 가이드의 필수·권장·비권장·함께 못 쓰는 스킬 → ③ 컨셉의 뼈대 → ④ 스킬 분류·상황 조건으로 비교 후보 결정 → ⑤ 기회비용으로 레벨·부위 결정.

## 무기 특성

동작 코드값은 [스킬 사전](SKILLS.md)의 액션 조건과 같다: 모으기 · 가드 · 태클 · 카운터 · 공중 · 저스트 회피 · 회피 · 탄·화살 · 변형 · 포격·병 · 강화 상태 · 특수 스킬 · 가드·카운터 보유 (가드나 카운터 동작이 있음. 주력으로 쓰는지와 무관 = 회피 없이 자리를 지켜 불퇴전을 유지할 수 있음, 2026-10-18 사용자. 가드·카운터 코드는 '주요 딜 메커니즘' 기준) · 후방 (솔로 플레이에서도 몬스터 뒤를 잡기 쉬움 = 기습 발동 조건, 2026-10-18 사용자) · 연속 타격 (공격 간격 4초 이내로 10타 이상 유지 가능 = 연격 발동 조건, 2026-10-18 사용자. **중간**은 비고에만 적어 두는 내부 참고 구분이며 빌드에서는 어려움(없음)과 같이 취급한다 — 쉬운 무기나 더 쉬운 스킬이 있으면 중간 스킬을 굳이 넣지 않으므로. 향후 연속 공격 계열 신규 스킬용).

- **있음:** 그 동작이 주요 딜 메커니즘에 들어간다 → 해당 액션 조건 스킬을 후보로 쓴다.
- **없음:** 들어가지 않는다 → 해당 액션 조건 스킬을 제외한다.
- **(적히지 않음) = 미확인:** 제외하지 않는다. 지침이 채워지면 있음/없음으로 옮긴다.
- 행 단위는 무기 × 스타일(기본 / 스타일1 / 스타일2). 같은 스타일 안의 성향(예: 한손검 기본의 가드 연계 / 폴배시)은 이 표가 아니라 운용 가이드에서 나눈다.
- 지침이 없는 무기는 세 스타일에 같은 값(공식 근거로 확인된 것만)을 적어 두었다. 지침이 들어오면 스타일별로 고친다.
- **초안 (2026-10-16):** 사용자 지침과 공식 스킬 설명에서 확인된 것만 채웠다. **실행 로직은 이 표를 쓴다** (`auto-build.js`의 `AB_TRAITS`, `tools/auto-build-rules-test.js`가 대조, 2026-10-18). 액션 조건이 있는 스킬은 있음이면 ON, 없음·미확인이면 OFF로 계산한다 (미확인은 발동 가정 칩으로 켤 수 있음). 운용 규칙 표에 적힌 스킬은 이 표와 상관없이 ON. 회피는 모든 무기 공통이라 거르지 않는다.

## 공통 운용 규칙

- **록온:** 근접 무기는 록온 1을 기본 필수로 확보한다 (화면에서 끌 수 있음). 원거리 3종은 쓰지 않는다.
- 스타일 미지원 무기나 '스타일 없음'은 해당 무기의 기본스타일 규칙을 쓴다.
- 운용 규칙 스킬은 화면의 제안 카드에서 하나씩 끌 수 있다. 사용자가 직접 지정한 스킬은 유지한다.
- 비권장 = 자동 보충 제외. 다른 유효 스킬이 붙은 겸용 장비는 금지하지 않는다.
- 셀 표기: `스킬 최소~목표` (같으면 한 숫자, `MAX`=스킬 최대). 권장은 최소0. 여러 개는 ` · `, 없으면 `—`.
